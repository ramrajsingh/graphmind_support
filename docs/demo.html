The problem

A customer calls back: “My account still isn't working.” Most support bots start from zero. They ask the customer to explain again, suggest the fix that already failed, and forget that the customer spoke Hindi yesterday and English today. The answer depends on how things relate: this customer, this ticket, the steps already tried, and the fixes that worked for others with the same problem.

What we built

Asha is a voice agent that uses FalkorDB as its context layer. On every call she loads the customer's subgraph: products, tickets, steps tried, and summaries of earlier calls. She matches new problems to known issues with vector search, and gets the next fix with a multi-hop traversal: known issue → ranked fixes, minus what this ticket already tried. When a fix works, she writes it back as shared knowledge, so the next customer benefits in any language.

🎙 Caller · any language→Sarvam Saaras v4 STT→Translate → English→LLM + 5 memory tools⇄FalkorDB · Cypher→Translate → caller's language→Bulbul v4 TTS 🔊

Multi-hop: the next fix for a callback

MATCH (c:Customer {customer_id:$cid})-[:OPENED]->(t:Ticket)
OPTIONAL MATCH (t)-[:MATCHES]->(k:KnownIssue)
OPTIONAL MATCH (t)-[:TRIED]->(f:TroubleshootingStep)
WITH t, k, collect(f.name) AS tried
OPTIONAL MATCH (k)-[rb:RESOLVED_BY]->(s)
WHERE NOT (t)-[:TRIED]->(s)
WITH t, k, tried, s ORDER BY rb.rank
RETURN t.id, k.name, tried, collect(s.name) AS untried

Preloaded at call start, so a callback is answered with no extra tool round trip (31 ms query).

Vector search + traversal: a new problem

CALL db.idx.vector.queryNodes('KnownIssue','embedding',6,
     vecf32($vec)) YIELD node AS k, score
WITH k, score WHERE score < 0.5
OPTIONAL MATCH (k)-[:AFFECTS]->(p:Product)
WITH k, score, p WHERE p.key = $product
MATCH (k)-[rb:RESOLVED_BY]->(s:TroubleshootingStep)
OPTIONAL MATCH (:Ticket {id:$tid})-[tr:TRIED]->(s)
RETURN k.name, score,
  collect({step:s.name, tried: count(tr) > 0})

Unrelated problems (“router LED blinking orange”) correctly match nothing, which triggers learning.

Learning loop: memory that improves

When a caller confirms a fix worked, Asha adds a RESOLVED_WITH link on the ticket and promotes the fix to shared knowledge: a RESOLVED_BY {learned:true} link on the matched known issue, or a new embedded KnownIssue created from the ticket. Tested live:

  1. Rahul (Hindi): “Mera router ka light orange blink kar raha hai.” No known issue matches. A ticket is opened. A factory reset fixes it, so a new KnownIssue is created with that fix.
  2. Ananya (Bengali): “আমার Acme Smart Router এর আলো কমলা রঙে জ্বলছে-নিভছে” (different words, different language). Vector search finds Rahul's learned issue, and Asha suggests the factory reset first.

Explainable by design

Every turn returns the exact Cypher it ran and how long each query took. The UI shows them under Agent memory calls & Cypher, next to a live graph view where the nodes and edges used in the answer are highlighted. Judges can see why Asha suggested a step: which known issue matched, which steps were excluded as TRIED, and in what rank order the rest came.

Sarvam multilingual layer

Hear and understand

Saaras v4 transcribes 22 Indian languages plus English, including mixed speech like Hinglish, with language detection and keyterms (“Acme Pay”, “2FA”). Sarvam Translate turns each turn into English, so one language-neutral graph serves every language: a ticket opened in Hindi is continued in Tamil or English.

Speak naturally

Replies are translated back in classic-colloquial style, keeping tech terms in English, and spoken by Bulbul v4 with a persona voice per language. Typed caller lines are read aloud in a male or female caller voice, so a typed demo sounds like a two-person call. preferred_language on the Customer node sets the greeting language.
